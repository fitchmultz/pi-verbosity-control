# Project instructions

## Engineering standard

- This repository follows the Strict Oxlint and Oxfmt Engineering Standard v5.1.2; the adopted copy is `docs/quality/strict-oxlint-oxfmt-5.1.2.md` and the adoption record is `docs/quality/adoption.md`. `.oxlintrc.json` and `.oxfmtrc.json` carry that configuration, `docs/quality/quality-exceptions.md` holds the recorded exceptions (QX-001 allowance, QX-002 directive inventory, QX-003 formatting mapping), and `npm run policy:check` fails when the effective configuration, tool floors, source coverage, or the authorized directive inventory drifts. Rule and option changes are policy decisions.
- `npm run check` is the pre-push gate: policy conformance, format check, lint (type-aware), typecheck, tests, and pack check. Gates run independently through `scripts/run-gates.ts`, so one failure cannot hide another. Findings are fixed in code; the repository keeps only the recorded lint-disable directives and zero TypeScript suppression comments. Test diagnostic fixtures live under `tests/probes/` and are enforced by `npm run quality:probes`, never by suppression.

## Dependency maintenance

- Frequently and proactively check releases and make appropriate upgrades across maintained packages and all runtime, development, build, test, and tool dependencies, prioritizing the latest stable official Pi and the intended maintained Pi fork. Routine in-scope maintenance needs no repeated approval; delivery remains subject to existing authority and gates.
- Review crossed release notes, changelogs, migration guidance, and security advisories before upgrading. Verify real APIs and contracts across supported hosts and platforms using each target's exact SDK/CLI and compatible, consistently locked dependency cohort, including host-supplied companions. Preserve lockfile policies, peer contracts, and support floors; a matching version string or locked snapshot alone is not latest-host qualification.
- Adopt beneficial current conventions, patterns, APIs, and functionality instead of extending deprecated or obsolete approaches. Preserve supported behavior and independent use; align affected callers, documentation, generated surfaces, and fixtures through their canonical owners.
- Follow [tests and host qualification](README.md#tests) and [scoped release rules](README.md#releases). Run all applicable required lint, format, type, test, build, package, native, CI, and review gates; report exact targets, commands, results, skips, and unverified limits honestly. Documentation checks alone do not qualify runtime behavior. Never weaken safety, checkers, fixture contracts, or supported-target requirements to make an update pass.
- Roll out updates controllably with a rollback path through existing review, approval, and release gates; honor every explicit hold. This authorization is not blanket permission to publish, install into or restart an active runtime, disclose private data, or change global model or authentication settings.
